## 1. 기업 개요

| 구분 | 내용 |
|---|---|
| 기업명 | 주식회사 워크메이트에이아이 (WorkMate AI) |
| 설립연도 | 2024년 3월 법인 설립 |
| 소재지 | 경기도 용인시 (본사 및 개발팀) |
| 임직원 수 | 9명 (개발 7명, 대표이사·사업개발 2명) |
| 기업규모 | 중소기업 / 창업 3년 미만 초기 스타트업 |
| 주요 제품/서비스 | 사내 문서 기반 AI 업무비서 「워크메이트 어시스턴트」 (SaaS) |
| 주요 고객군 | 사내 규정·매뉴얼·보고서가 많은 중견·중소기업, 대기업 지원부서 |
| 최근 매출 | 2024년 0원 / 2025년 0원 (현재 무료 PoC 운영 단계) |
| 투자유치 현황 | 외부 투자 유치 없음 (정부 창업지원사업 사업비로 개발 진행) |

당사는 기업 내부에 쌓인 규정·매뉴얼·보고서를 생성형 AI로 즉시 활용할 수 있게 만드는 Enterprise AI 스타트업이다. 창업진은 그룹웨어·사내 포털 구축 경험을 바탕으로 RAG(검색 증강 생성) 기반 기업용 생성형 AI 서비스를 개발해 왔다.

설립 이후 두 차례 정부 창업지원사업에 선정되어 총 1억 3,700만원의 사업비로 MVP 개발과 테스트기업 PoC를 진행하였다. 현재 유료 전환과 시장 확산을 준비하고 있다.

## 2. 사업 추진 배경 및 문제 정의

### 2.1 고객이 겪고 있는 문제

기업의 업무 지식은 대부분 문서로 존재하지만 찾아 쓰기는 어렵다. 당사가 중견·중소기업 직원 31명을 인터뷰한 결과, 대부분이 "규정이나 이전 보고서를 찾는 데 하루 30분 이상을 쓴다"고 답했다.

- 사내 규정이 수시로 개정되어 어느 버전이 최신인지 확인하기 어려움
- 신규 입사자가 매뉴얼을 찾기 위해 선임에게 반복 질문함
- 그룹웨어 검색은 파일명 위주여서 본문 내용을 찾기 어려움

### 2.2 기존 방식의 한계

| 구분 | 방식 | 한계 |
|---|---|---|
| 그룹웨어 검색 | 파일명·키워드 기반 검색 | 본문 맥락 검색 불가, 문서를 직접 열어 읽어야 함 |
| 범용 생성형 AI 챗봇 | 직원 개인이 외부 AI 서비스에 질문 | 회사 내부 문서를 알지 못해 맞춤 답변 불가 |
| 구축형 AI 플랫폼 | SI 방식으로 사내 AI 시스템 구축 | 수억 원대 구축비와 수개월의 기간, 중소기업 도입 곤란 |

### 2.3 해결하려는 문제

당사는 **별도 구축 없이 문서 업로드만으로 당일부터 사용할 수 있는 기업용 생성형 AI 업무비서**를 제공하고자 한다. 직원은 사내 문서에 근거한 답변을 출처와 함께 받고, 요약과 초안 작성까지 한 화면에서 처리한다.

## 3. 제품·서비스 개요

| 구분 | 내용 |
|---|---|
| 제품명 | 워크메이트 어시스턴트 (WorkMate Assistant) |
| 구성 | 웹 대화형 화면, 문서 업로드·관리 콘솔, 사내 메신저 연동 봇(개발 중) |
| 주요 기능 | 사내 규정·매뉴얼 질의응답, 보고서 요약, 보고서·공문 초안 작성, 근거 문서 표시 |
| 사용 방식 | 관리자 문서 업로드 → 자동 분할·임베딩 → 직원 질문 → 외부 상용 LLM API로 답변 생성 → 근거 문서와 함께 제시 |
| 제공 형태 | 클라우드 SaaS (당사 클라우드 환경에서 운영) |
| 핵심 가치 | 업로드 즉시 사용, 한글(HWP) 문서 처리, 근거 제시, 낮은 비용 |

고객사 관리자가 워크스페이스를 만들고 문서를 올리면, 해당 워크스페이스에 초대된 직원은 누구나 동일한 문서 범위 안에서 검색하고 질문할 수 있다. 부서별 워크스페이스 분리 운영도 가능하다.

답변 생성에는 성능이 검증된 해외 상용 LLM API를 활용하며, 직원의 질문과 함께 검색된 문서 본문 일부가 API로 전달되어 답변이 만들어진다. 최신 모델 성능을 바로 활용할 수 있어 초기 스타트업에 가장 합리적인 구조라고 판단한다.

## 4. 핵심 기술 및 개발 현황

### 4.1 핵심 기술

- **한글 문서 전처리**: HWP 문서의 표·개조식 구조를 인식해 의미 단위로 분할하는 자체 파서
- **하이브리드 검색**: 키워드 검색과 벡터 검색을 결합해 규정 조항·수치 질의 품질 향상
- **근거 기반 답변**: 답변마다 참조 문서명·페이지를 표시
- **초안 작성 Agent**: 과거 보고서 구조를 참고해 초안을 단계적으로 작성하는 AI Agent 기능

### 4.2 개발 경과

| 시기 | 개발 내용 | 비고 |
|---|---|---|
| 2024년 상반기 | 법인 설립, RAG 프로토타입 개발 | 공개 문서로 기능 확인 |
| 2024년 하반기 | HWP 파서 개발, 웹 화면 구축 | 정부 창업지원사업 선정 |
| 2025년 상반기 | MVP v1.0 출시, 테스트기업 PoC 착수 | 클라우드 SaaS 형태 |
| 2025년 하반기 ~ 2026년 상반기 | 테스트기업 5개사 PoC 운영, v1.4 배포 | 아래 5장 참조 |
| 2026년 하반기 | 메신저 연동 봇, 초안 작성 Agent 개발 | 현재 진행 중 |

### 4.3 성능 시험 결과

| 항목 | 결과 | 시험 조건 |
|---|---|---|
| 답변 정확도 | 88% | 당사 내부 평가 |
| 근거 문서 제시율 | 93.6% | 답변 중 출처 문서가 표시된 비율 |
| 평균 응답 시간 | 4.7초 | 문서 1,000건 워크스페이스 기준 |

답변 정확도는 당사 개발팀이 마련한 질의 평가셋으로 측정한 내부 평가 결과다. PoC 사용자 만족도도 대체로 4점 이상(5점 만점)으로 실무 활용에 충분하다고 본다.

### 4.4 보유 데이터 및 운영 현황

당사는 PoC 과정에서 고객사 문서 약 1만 4,000건을 처리하였고, 질의응답 로그 약 6,300건을 축적하였다. 로그는 답변 품질 개선을 위해 당사 클라우드 서버에 보관하고 있으며, 보관 기간이나 삭제 시점은 따로 정하지 않고 고객사 요청이 있을 때 개별 삭제하고 있다.

업로드 문서의 개인정보 포함 여부는 고객사 관리자가 업로드 전에 판단하도록 안내하고 있으며, 시스템 차원의 별도 처리 기준은 아직 두고 있지 않다. 접근제어는 워크스페이스 단위로 이루어지며, 문서별 열람 권한을 고객사 조직 정보와 연동하는 기능은 대기업 고객 수요를 확인한 후 개발할 계획이다.

### 4.5 현재 개발 중인 기술

PoC 고객사들은 "사내 메신저에서 바로 질문하고 싶다"는 의견을 공통적으로 주었다. 이에 메신저 연동 봇을 개발 중이며, 과거 보고서 양식을 참고해 초안을 구성하는 AI Agent 기능을 2027년 상반기 출시 목표로 고도화하고 있다.

## 5. 실증 및 고객 검증 현황

### 5.1 PoC 수행 실적

5개사 모두 무료로 진행하였으며, C사와 E사는 당초 4주 일정이었다.

### 5.2 실환경 운영 경험

A사에서는 34명이 4주간 실제 업무 중에 서비스를 사용하였고, "규정집을 뒤지는 시간이 크게 줄었다"는 반응을 얻었다. 운영 중 팀장급 전용 문서 일부가 일반 직원의 검색 결과에도 표시된다는 의견이 있어, 해당 문서를 워크스페이스에서 제외하는 방식으로 대응하였다. D사에서는 인사 규정과 함께 직원 명단이 담긴 첨부 문서가 업로드되었고, 고객사 요청에 따라 당일 해당 문서와 관련 로그를 삭제하였다.

C사는 2주 차에 고객사 정보보안팀이 데이터 처리 구조를 점검하면서 사용이 중단되었다. 당시 고객사는 외부 API로 전송되는 문서 범위, 로그 보관 기간, 보안인증(ISMS-P 등) 보유 여부를 묻는 점검표를 요청하였다. E사도 1주 차 이후 고객사 내부 보안 검토 일정과 맞물려 PoC를 이어가지 못했으며, 설치형(온프레미스) 제공 가능 여부를 문의하였으나 당사는 현재 클라우드 SaaS로만 서비스하고 있다.

### 5.3 실증 결과에 대한 당사의 판단

5개사 중 3개사가 예정된 기간 동안 PoC를 마쳤고 만족도가 평균 4점 안팎으로 나타난 만큼, **제품 성능과 현장 활용성은 충분히 검증되었다**고 판단한다. C사와 E사의 조기 종료는 금융업과 대기업 협력사 특유의 내부 절차와 일정상의 사정에 따른 것으로, 제품 기능에 대한 불만으로 종료된 사례는 없었다. 보안 관련 문의는 기업용 SaaS가 초기에 흔히 거치는 절차이며, 고객 수가 늘어나는 과정에서 안내 자료를 정비해 나가면 충분하다고 본다.

## 6. 시장 및 사업화 현황

### 6.1 목표 시장

기업용 생성형 AI 시장은 가장 빠르게 성장하는 AI 분야 중 하나로, 국내 시장도 연평균 30% 이상 성장할 것으로 예상한다. 1차 목표 시장은 경기 남부(용인·수원·화성·성남) 임직원 50~500명 규모 중견·중소기업이며, 레퍼런스 확보 후 대기업 지원부서(인사·총무·품질)로 확대할 계획이다.

### 6.2 사업화 진행 현황

| 항목 | 현황 |
|---|---|
| 잠재고객 리스트 | 약 120개사 (산업단지 입주기업 중심) |
| 상담·미팅 진행 | 17개사 |
| PoC | 5개사 착수, 3개사 완료 (모두 무상) |
| 도입의향서(LOI) | 없음 |
| 유상 계약 / 매출 / 반복매출 | 없음 |
| 영업 인력 | 전담 인력 없음 (대표이사와 사업개발 담당 1명이 병행) |
| 영업 채널 | 창업지원기관 소개, 지인 네트워크, 스타트업 박람회 1회(2025년) |
| 가격 정책 | 사용자 1인당 월 구독형(월 1만 9,000원 안) 검토 중 |

구축형 플랫폼 대비 10분의 1 이하 비용으로 도입할 수 있다는 점을 핵심 메시지로 삼고 있다.

### 6.3 경쟁 현황

글로벌 빅테크, 대기업 계열 SI, 국내 스타트업 다수가 시장에 진입해 있다. 일부 경쟁사는 보안인증, 설치형 제공 등 AI 보안 역량을 강조하고 있으나, 당사는 중견·중소기업 시장에서는 도입 속도와 비용, 한글 문서 처리 품질이 더 중요한 선택 기준이라고 판단한다.

### 6.4 해외 시장

해외 진출 경험은 없으며, 국내 기반 확보 후 일본 시장을 검토할 계획이다.

| 기존 고객 | 무료 PoC 5개사 (유료 고객 없음) |

### 7.1 당사의 강점

개발 인력 비중이 약 80%로 고객 피드백을 빠르게 반영할 수 있다. 국내 기업 문서의 상당수를 차지하는 HWP 문서를 표 구조까지 인식해 처리한다는 점도 해외 솔루션 대비 분명한 강점이다.

### 7.2 보완이 필요한 역량

당사의 가장 큰 약점은 **인지도**다. 써 본 고객은 만족하지만 당사를 알고 찾아오는 고객은 거의 없다. 영업·마케팅 전담 인력과 대기업 구매부서 접근 경로도 부족하다. 아울러 고객사 보안 담당자의 질문에 바로 답할 표준 안내 자료도 정리할 필요가 있다.

## 8. 향후 사업계획

당사는 **제품 성능은 이미 시장에 내놓기에 충분하며, 지금 필요한 것은 더 많은 기업이 당사 제품을 알고 직접 써 보게 하는 것**이라고 판단한다. 시장 선점 효과가 큰 만큼 2027년 상반기까지 공격적인 마케팅으로 인지도를 확보하는 것이 중요하다.
